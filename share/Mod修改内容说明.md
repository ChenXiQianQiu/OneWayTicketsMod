# 再再启程 One Way Tickets · Mod 修改内容说明

## 当前包含的 Mod

### 再再启程 资源编辑（OneWayTicketsMod）v0.2.3

游戏内按 **F1** 打开面板（可在面板「设置」页改键）。全部功能都是直接读写游戏自己的对象，
不扫描内存、不写死地址，重开游戏也不会失效。

**概览**
- 一键满资源：已解锁的营地币全部拉满 + 局内金币拉满 + 车辆回满。
- 补建未获得的营地币：把「已解锁但从没获得过」的币补成 0，之后才能在营地里显示和修改。
- 解锁全部营地币：把数据表里所有营地币标记为已解锁。
- 实时状态：所在场景、营地币条目数、局内金币、车辆耐久、车速、旅人数量、昏迷旅人数、异常设备数。

**营地资源**
- 里程券 / 食物 / 建材 / 珍宝 / 秘能等逐项编辑：输入框改值 + 应用，或直接 `+1万` / `满`。
- 支持搜索、显示数据表里全部营地币、全部 +1万 / 全部拉满。
- 改完营地左上角资源栏会立刻刷新（游戏原本只在车库、休息区等操作后才刷新）。

**局内**
- 局内金币：直接改，背包 UI 立刻同步。
- 车辆耐久 / 耐久上限：改值或一键回满。
- 无限耐久：每 0.2 秒把耐久补回上限，面板关掉也继续生效（记得退出探索时关掉）。
- 车辆速度（v0.2.0 新增，v0.2.1 修复锁定）：
  - 「设为」输入框直接写车速，下一帧就按新速度跑；另有 `+5` / `-5` / `归零` 快捷键。
  - 「取当前」「取最高」：把当前车速 / 本次探索跑出过的最高车速填进输入框。
  - 「锁定车速」：打开后每帧把车速钉在锁定值，不会被减速、不会掉速。
    锁定只在「地面行驶」时生效，跳跃 / 滞空不干预，避免影响落地判定。
    锁定靠每帧回写实现，面板上的数值可能有 ±0.1 的抖动，属正常现象。

**旅人**
- 旅人不会晕车（v0.2.0 新增，v0.2.1 换实现，v0.2.3 再换）：开启后每 0.5 秒把所有旅人的
  「免疫冲击昏迷」标志置位，车辆颠簸、设备受击震动都不会再让人进入 Coma（昏迷，状态栏显示「昏迷」）。
  - **v0.2.3 起不再给旅人塞「油门焊死」词缀**。旧做法虽然能进存档，但词缀本身会给车轮加牵引力，
    同一个人身上一旦出现两份（存档里一份 + 进场景后补一份），牵引力就会叠加，
    车速被顶到极高之后车会冲出地图、画面全黑。
    现在改成纯运行时置位：不写存档、不改任何游戏数据，效果完全一样。
  - 打开开关时会顺手做一次「重复词缀清理」：发现谁身上有多份「油门焊死」就只留一份，
    把历史版本留下的重复数据修掉（日志里会写清清理了谁）。
  - 面板上会显示「队伍 N 人，自带『油门焊死』M 人，已清理重复词缀 K 份」。
  - 关掉开关时，身上自带该词缀的旅人仍保持免疫（那是游戏自己给的），其它人恢复原状。
- 全部唤醒：把当前昏迷的旅人一次性叫醒（不改属性，只清昏迷）。
- 休息区旅人也能上工位（v0.2.1 新增，v0.2.2 换实现）：在旅人列表点「选」挑人，再到「工位分配」里点「安排」，
  休息区旅人同样可以上工位。
  - v0.2.0 是改游戏的点选判定，实测在本作无效（Harmony 补丁根本不执行）；
    v0.2.1 改成面板直接绑工位，数据上绑上了，但人还在休息区，游戏里看不出效果。
  - **v0.2.2 改成「先把人真的换到操作中（前排），再上工位」**：
    用的是游戏自己的 `TakeCharacterToFront` / `TakeCharacterToBackup`，
    底部「操作中 / 休息区」两排会跟着变，设备也认他。
  - 操作中满 6 人时，会自动把一个「没在岗、也没占工位」的前排旅人换到休息区（会提示换了谁）。
  - 旅人列表每行现在有「上阵」（休息区 → 操作中）/「换下」（操作中 → 休息区）按钮，
    也可以先手动换人，再用游戏原本的方式点工位上工。
  - 全程只有一份，不会被塞进两个列表，存档不会写重、读档不会变成两个人。
  - 每个工位还能「撤下」，把上面的人撤走。
- 旅人列表：显示操作中 / 休息区、是否在岗、当前状态（正常 / 昏迷 / 亢奋），
  每行带「上阵 / 换下」「选」按钮。
- 修了一个按钮点不到的 UI 问题：列表右侧的按钮原本会被推到面板可见区域外面
  （v0.2.1 的「撤下」就是这样消失的），现在按钮紧跟在状态后面，都能正常点击。

**设备**（v0.2.0 新增页签）
- 设备免疫异常状态（v0.2.2 换实现）：开启后车上设备不会被点燃、机械故障、腐蚀、缠绕、打湿。
  - 做法是每 0.2 秒把设备钉在游戏自己的「免疫」状态上——游戏判定异常的第一行就是「免疫则跳过」，
    所以五种异常都进不来，也不会再出现红色警告图标。
  - 面板上会显示「免疫中 N 台」，这是被钉住的状态，属正常现象；关掉开关立刻恢复成「正常」。
  - 只免疫这五种异常状态，**普通掉血仍然会掉**（要免掉血请用「局内」页的无限耐久）。
  - 相关工具（灭火器、除酸等）会因为设备不再异常而用不上，这是作弊的必然结果。
- 全部清除：把当前已经进入异常的设备一次性恢复（走的是游戏进安全区的同一套清理逻辑，图标会一起消失）。
- 设备列表：显示每台设备的槽位、名字、耐久、当前状态（正常 / 免疫中 / 五种异常），报废的用红色标出。

**容错**（v0.2.3 新增）
- 黑屏守卫（设置页，默认开）：过场 / 进安全区的黑幕超过 3 秒不消失就把当时的游戏状态写进
  `BepInEx/LogOutput.log`，超过 8 秒自动收掉黑幕并解除 ESC 锁定，不用再重启游戏。
- 顺带监测车速 / 车辆位置 / 相机坐标是否被写成 NaN（这种状态下画面必然全黑、游戏却不报错），
  发现后立刻把车速归零并记录现场。
- 车速写入加保护：路况数据异常（NaN / 无穷大）时直接丢弃，车速超过 300 也会被限制回来。

**设置**
- 改键、满资源目标值、系统字体开关、点击拦截开关、黑屏守卫开关、环境诊断（含各开关的当前状态）。

**注意事项**
- 营地资源属于存档数据，改完要回营地或存档才会落盘，直接退游戏会丢。
- 局内金币 / 车辆耐久 / 车速只在本局有效，回营地结算后才写进存档。
- 「不会晕车」「设备免疫异常」「黑屏守卫」会写进 `BepInEx/config/onewaytickets.resedit.cfg`，重启游戏仍然生效；
  「无限耐久」和「车速锁定」只在本次运行内有效，重开一局要重新确认。
- 面板打开时默认会临时拦住游戏的 UI 点击（防止点面板同时点到底下的按钮）；
  万一某个场景 UI 卡住不动，在「设置」里关掉「面板打开时挡住游戏点击」。
- 仅供单机自娱，别拿去联机或传播修改后的存档。

## 更新记录

### 2026-10-24 · v0.2.3

修「从战斗点前往安全点时画面全黑」。

1. **「旅人不会晕车」改成纯运行时置位，不再写词缀**
   - 旧实现给每位旅人塞一份「油门焊死」词缀。这个词缀的 `EnterTeam()` 除了免疫昏迷，
     还会给车轮加牵引力（`wheel_tractive_force_role += wheel_tf`）。
   - 只要同一个人身上出现两份（存档里已经有一份、进场景后又被补一份），
     牵引力就翻倍；词缀越多车越猛，车速被顶到极高之后
     `caravan_pos += velocity/120` 会把车送出地图，相机跟着 `caravan_pos` 走，
     画面就全黑了——UI 还在、游戏逻辑照跑，很容易被当成「卡死」。
   - 现在每 0.5 秒直接把 `isImmuneToStun` 置 true（`ApplyShockForce` 第一行就 return，
     效果和词缀完全一样），不写存档、不改牵引力、不碰任何游戏数据。
   - 打开开关时自动做一次「重复词缀清理」：同一人身上有多份「油门焊死」只留一份，
     把旧版本可能留下的重复数据修掉。

2. **新增「黑屏守卫」**（设置页，默认开）
   - 过场 / 进安全区的黑幕如果超过 3 秒还不消失，把当时的游戏状态写进 BepInEx 日志
     （时间缩放、安全区标志、车速、车辆位置、ESC 是否被锁、旅人/设备数量、牵引力）；
     超过 8 秒仍未恢复就自动收掉黑幕并解除 ESC 锁定，先把画面还给玩家。
   - 同时监测「车速 / 车辆位置 / 相机坐标」有没有被写成 NaN —— 这种状态下画面必然全黑，
     但游戏不会报任何错。发现后立即把车速归零并记录现场。

3. **车速写入加保护**
   - 路况曲线插值异常时 `road_slope` 会返回 NaN / ±Infinity，
     旧代码会把它算进 `caravan_velocity`，直接把车辆位置变成 NaN（同上，画面全黑）。
     现在写入前校验，异常值直接丢弃；车速超过 300 也会被限制回 300。

4. 打开 BepInEx 的 Unity 日志落盘（`BepInEx/config/BepInEx.cfg` → `WriteUnityLog = true`），
   方便排查同类问题；不需要时可以改回 `false`。

### 2026-10-24 · v0.2.2

修 v0.2.1 遗留的两个问题（都是「开关开了但游戏里看不到效果」）。

1. **设备还是会有异常** → 改成轮询钉住「免疫」状态
   - 原因：v0.2.0/v0.2.1 的免疫靠 Harmony 前置补丁拦 `applied_outlier`，
     而本作 Harmony 补丁完全不执行（v0.2.1 已查明），所以设备照烧照腐蚀。
   - 现在：`DeviceGuardService.Tick` 每 0.2 秒遍历车上所有设备，
     先 `EnterSafeArea()` 清掉已经挂上的异常（图标一起消失），
     再把 `state` 钉在 `immue` 并续上 `immu_countdown`（私有字段，反射读写）。
     `applied_outlier` 的第一行就是 `if (state == immue) return;`，所以五种异常都进不来。
   - 关掉开关会把设备还原成「正常」，不留残留。
   - 面板「设备」页新增「免疫中 N 台」，方便确认真的钉住了。

2. **休息区旅人上工位还是不行** → 改成真的把人换到操作中
   - 原因：v0.2.1 是绕开判定直接 `set_worker`，数据绑上了，但人还在后备队列表里，
     底部「操作中」那排不会变，设备/词缀也不会真的吃到他。
   - 现在：先 `TakeCharacterToFront` 把人换到前排，再走 `set_worker` /
     `SetCharacterWorking` / `EnterCubicle`；前排满 6 人就自动换下一个空闲的人（会提示换了谁）。
   - 旅人列表每行新增「上阵 / 换下」按钮，可以手动换人；
     也可以换完人之后用游戏原本的方式点工位上工。
   - 已验证：休息区「乌日娜」→ 安排到「弹库装填」→ 提示
     「乌日娜 已换到操作中，搞事 去了休息区 → 弹库装填」，
     游戏内工位面板底部「操作中」那排真的多出了她。

3. 顺手修的 UI 坑
   - 列表行内原来用 `FlexibleSpace` 把按钮推到右边，但页面外层滚动区的可见宽度比布局宽度窄，
     按钮会被画到面板外面（看得见一部分、点不到）——v0.2.1 的「撤下」就是这样消失的。
     现在按钮紧跟在内容后面左对齐，「营地资源」页的「刷新」也一并改了。
   - 「设备」页的状态列区分「正常 / 免疫中 / 五种异常」三种配色。

### 2026-10-24 · v0.2.1

修 v0.2.0 里「开了开关却没效果」的三个问题。根因是同一个：
**本作的 Harmony 补丁根本不执行**（实测 `CaravanMover_Run.do` 的计数补丁跑了 0 次），
所以 v0.2.0 里靠补丁实现的三个功能全部失效。v0.2.1 把它们全部改成不依赖 Harmony 的写法。

1. **车速锁定没效果** → 改为每帧回写
   - 原因：v0.2.0 的补丁挂在 `CaravanMover.move`，这个方法只有一行反射调用，被内联后补丁失效。
   - 现在：`CaravanSpeedService.Tick` 每帧直接把速度写回目标值，不再依赖补丁。
   - 顺带修了一个精度问题：`CaravanMover_Run.do` 末尾会把速度重设成「沿坡面方向、模长不变」的向量，
     只写 `velocity.x` 会被按 `cos(坡度)` 缩掉一截；现在按坡度反推模长再重建整个向量。

2. **旅人不会晕车没效果** → 改为补「油门焊死」词缀
   - 原因：v0.2.0 的补丁挂在 `Character.ApplyShockForce`，同样被内联掉。
   - 现在：给每位旅人补一份游戏自带的 `CP_Reckless_Driving`（词缀 id 162004，游戏内叫「油门焊死」），
     它的 `EnterTeam()` 就是 `owner.isImmuneToStun = true`，属于改数据，不受内联影响。
   - 0.5 秒轮询兜底：新入队 / 换人 / 读档后自动补齐；关闭开关只回收本 Mod 补的那份。
   - 已验证：读档后 9 名旅人全部带词缀，面板显示「队伍里 9 人已有」。

3. **休息区旅人上工位没效果** → 改为面板直接分配
   - 原因：v0.2.0 改 `Character_Helper.GetAllCharacters`，v0.2.1 早期改 `Cubicle_Helper.SetCubicle`，
     两个补丁都不执行。
   - 现在：「旅人」页新增「工位分配」卡片：旅人列表点「选」→ 工位列表点「安排」，
     直接调游戏自己的 `set_worker` / `SetCharacterWorking` / `EnterCubicle`，绕开点选判定。
   - 已验证：休息区旅人「若木」→「近战攻击」工位，列表状态从「空闲」变「在岗」。

其它调整：

- 面板默认高度 610 → 720，旅人页能同时放下开关卡片、旅人列表和工位分配。
- 「词缀」一行会显示词缀 id、队伍里已有词缀的人数、本次新补的人数，方便排查。
- `_work/screen_tool.py` 增加 `wheel` 命令（滚轮），用于滚动面板列表做验证。
- 保留三个 Harmony 补丁：本作虽然不执行，但万一以后生效，行为会更精确（尤其车速）。

### 2026-10-24 · v0.2.0

按需求新增三个功能：

1. **旅人不会晕车**（「旅人」页）
   - 游戏机制：`CharacterMgr.tick` 每物理帧用车辆纵向加速度算冲击力，
     超过 `role.coma_g` 阈值后按概率让旅人进入 `Coma`（昏迷）。
     全游戏只有 `Character.ApplyShockForce` 一处会创建昏迷，所以在这里做前置补丁。
   - 效果：车辆颠簸、设备受击震动都不再让旅人晕倒；附带「全部唤醒」按钮。
   - 开关持久化到配置文件。

2. **设备免疫异常状态**（新增「设备」页）
   - 游戏机制：燃烧 / 机械故障 / 腐蚀 / 缠绕 / 潮湿五种异常，唯一入口是
     `Device.ITarget.applied_outlier`（显式接口实现，编译后名字是 `World.ITarget.applied_outlier`）。
   - 效果：所有施加异常的入口都被跳过，设备永远停在「正常」；
     附带「全部清除」（走 `Device.EnterSafeArea`，图标会一起消失）和「设备列表」。
   - 只免疫异常，普通掉血仍生效。
   - 开关持久化到配置文件。

3. **车辆速度：直接设置 + 锁定**（「局内」页）
   - 游戏机制：车速就是 `WorldContext.caravan_velocity`，
     `CaravanMover_Run.do` 每帧 `velocity += acc/120` 后按 `velocity.x` 推进，
     **没有速度上限字段**，所以「保持最大值」只能靠每帧钉住。
   - 效果：输入框直接设置；「取当前 / 取最高」一键填值；「锁定车速」每帧写回目标值（只在 Run 状态生效）。

其它调整：

- 状态条新增「车速」；概览页新增「车速 / 昏迷旅人 / 异常设备」三行。
- 旅人列表的状态从显示类名（`Coma`）改为中文（昏迷 / 亢奋）。
- 补丁挂载改为逐个 try/catch：单个补丁点失效不会连带其它功能一起不可用。
- 新增 `_work/screen_tool.py`：纯 ctypes 的截图 / SendInput 点击工具，用于本机验证。

### 2026-10-24 · v0.1.0

- 首个版本 v0.1.0。
- 从 Cheat Engine 表（`再再启程 资源编辑表.CT`）迁移为 BepInEx 插件：
  CE 版依赖「扫描 vtable 找单例 + 猜字段偏移」，游戏更新或场景不同就容易定位失败；
  Mod 版在游戏进程内直接反射访问 `CommonContext` / `BackPackMgr` / `WorldContext` / `CharacterMgr`，
  不再有地址失效问题。
- 新增功能：
  - 休息区旅人可上工位（Harmony 后置补丁，返回副本，不污染前排列表）。
  - 无限耐久。
