# 再再启程 One Way Tickets · Mod 修改内容说明

## 当前包含的 Mod

### 再再启程 资源编辑（OneWayTicketsMod）v0.5.0

游戏内按 **F1** 打开面板（可在面板「设置」页改键）。全部功能都是直接读写游戏自己的对象，
不扫描内存、不写死地址，重开游戏也不会失效。

**概览**
- 一键满资源：已解锁的营地币全部拉满 + 局内金币拉满 + 车辆回满。
- 补建未获得的营地币：把「已解锁但从没获得过」的币补成 0，之后才能在营地里显示和修改。
- 解锁全部营地币：把数据表里所有营地币标记为已解锁。
- 实时状态：所在场景、营地币条目数、局内金币、车辆耐久、车速、旅人数量、昏迷旅人数、异常设备数。

**营地资源**
- 里程券 / 食物 / 建材 / 珍宝 / 秘能等逐项编辑：输入框改值 + 应用，或直接 `+1万` / `满`。
- 支持搜索、显示数据表里全部营地币、全部 +1万 / 全部拉满。
- 改完营地左上角资源栏会立刻刷新（游戏原本只在车库、休息区等操作后才刷新）。

**局内**
- 局内金币：直接改，背包 UI 立刻同步。
- 车辆耐久 / 耐久上限：改值或一键回满。
- 无限耐久：每 0.2 秒把耐久补回上限，面板关掉也继续生效（记得退出探索时关掉）。
- 车辆速度（v0.2.0 新增，v0.2.1 修复锁定）：
  - 「设为」输入框直接写车速，下一帧就按新速度跑；另有 `+5` / `-5` / `归零` 快捷键。
  - 「取当前」「取最高」：把当前车速 / 本次探索跑出过的最高车速填进输入框。
  - 「锁定车速」：打开后每帧把车速钉在锁定值，不会被减速、不会掉速。
    锁定只在「地面行驶」时生效，跳跃 / 滞空不干预，避免影响落地判定。
    **安全区里会自动停手**（v0.2.3 修）：安全区里改车速会被游戏算成剧烈颠簸，
    把旅人震晕之后又因为安全区不跑状态倒计时，人会一直晕着醒不过来。
    锁定靠每帧回写实现，面板上的数值可能有 ±0.1 的抖动，属正常现象。

**旅人**
- 旅人不会晕车（v0.2.0 新增，v0.2.1 换实现）：开启后给每位旅人补一份游戏自带的
  **「油门焊死」** 词缀。该词缀原本的效果就是 `isImmuneToStun = true`（免疫冲击昏迷），
  所以车辆颠簸、设备受击震动都不会再让人进入 Coma（昏迷，状态栏显示「昏迷」）。
  - 词缀会写进存档，读档后依然在；面板上会显示「队伍里 N 人已有，本次新补 M 人」。
  - 附带效果：词缀本身会给车轮加一点牵引力，这是游戏数据原本的设计。
  - 关掉开关只会撤掉本 Mod 补的那份，旅人自己带的词缀不动。
- 全部唤醒：把当前昏迷的旅人一次性叫醒（不改属性，只清昏迷）。
- **解除操作中人数上限**（v0.2.4 新增）：游戏把「操作中」写死成 6 人
  （`CharacterMgr.AddCharacter` / `TakeCharacterToFront` 都判 `characters.Count < 6`），
  超过 6 人的旅人只能待在休息区，而休息区旅人在游戏里点工位是没反应的。
  - 开启后直接绕开这道判定：整支队伍（最多 12 人）都能待在「操作中」，
    游戏自己的「点人头像 → 点工位」对所有人都成立，不再依赖任何补丁。
  - 读档 / 换局 / 中途招募后会自动把休息区的人重新拉上来；
    你在列表里手动点「换下」的人会留在休息区，不会被反复拉上来。
  - 面板上会显示「操作中 N / 12 人」，另有「全部上阵」按钮可以立刻拉满。
  - 已验证：读档后操作中从 6 人变 8 人（后来存档里 9 人也正常），
    游戏内工位面板底部「操作中」那排头像真的跟着变多。
  - **工位请用游戏自己的方式安排**：点底部「操作中」里的头像 → 点设备下面的工位格。
- 旅人列表：显示操作中 / 休息区、是否在岗、当前状态（正常 / 昏迷 / 亢奋），
  每行带「上阵（休息区 → 操作中）/ 换下（操作中 → 休息区）」按钮。
- **工位卡片**（v0.3.0 从「设置」页搬回本页）：
  - 「一键上工位」：把「操作中」里空闲的旅人一次性铺到车上的空工位。
    走的是和手点格子完全相同的入口，只遍历真的装在车上的设备，不会把人塞进已经拆掉的旧设备。
  - 「自动补满空工位」开关（默认关）：打开后每 2 秒检查一次，只要车上有空工位、
    「操作中」又有空闲旅人，就自动安排上，不用再手点。
    你正在游戏里手动点选旅人时（选中状态还没清），自动补位会跳过这一轮，**不会把你选好的人抢走**。
- **伙伴休息所（v0.4.0 新增）**：把「没见过」的角色点亮 / 把特殊伙伴直接收下。
  - 休息所里那些黑色剪影就是「没见过」的角色，游戏要求先在局内让他加入过队伍一次才点得开。
  - 「标记为已见」：解开这道门槛，之后仍要回休息所按正常流程花科技 / 资源收人（成就照常判定）。
  - 「特殊伙伴全收下」：跳过资源消耗，等于在休息所点了「解锁」；下次读档时游戏会把「初来乍到」成就补给你。
  - 支持逐人操作，列表实时显示未见过 / 已见未收 / 已是伙伴，并标出特殊 / 普通，改完立刻刷新休息所界面。
- 修了一个按钮点不到的 UI 问题：列表右侧的按钮原本会被推到面板可见区域外面
  （v0.2.1 的「撤下」就是这样消失的），现在按钮紧跟在状态后面，都能正常点击。
- ~~休息区旅人也能上工位~~ / ~~工位分配（安排 / 撤下 / 一键上工）~~：**v0.2.5 已删除**。
  前者实测完全没效果；后者会把人塞进「已经不在车上」的旧设备工位，属于真 bug。
  现在由「解除操作中人数上限」+ 游戏自带的点选流程替代，功能上不再需要它们。

**设备**（v0.2.0 新增页签）
- 设备免疫异常状态（v0.2.8 换实现）：开启后车上设备不会被点燃、机械故障、腐蚀、缠绕、打湿。
  - 做法是每 0.1 秒检查一次，一发现异常就调游戏自己的清理逻辑（`Device.EnterSafeArea`）
    连红色警告图标一起清掉，异常最多只存在 0.1 秒。
  - **v0.2.2 ~ v0.2.7 的旧做法有问题**：那时是把设备钉在游戏的「免疫」状态上，
    会让装备面板打开时报空引用，**该设备的工位格子直接消失、点不了**。v0.2.8 已改掉。
    代价是异常图标可能闪一下（≤0.1 秒）。
  - 面板上显示「已拦截 N 次」，是累计清掉的异常数量。
  - 只免疫这五种异常状态，**普通掉血仍然会掉**（要免掉血请用「局内」页的无限耐久）。
  - 相关工具（灭火器、除酸等）会因为设备不再异常而用不上，这是作弊的必然结果。
- 全部清除：把当前已经进入异常的设备一次性恢复（走的是游戏进安全区的同一套清理逻辑，图标会一起消失）。
- 设备列表：显示每台设备的槽位、名字、耐久、当前状态（正常 / 免疫中 / 五种异常），报废的用红色标出。

**奇物**（v0.5.0 新增页签，只在局内可用）
- 本局奇物：按种类聚合成一行（名称 / id / 数量 / 效果摘要），想看哪个不顺眼直接点「移除」。
- 添加奇物：数据表里全部奇物（195 条）都能加，可按名称 / id / 行为脚本名搜索，`+1` / `+3` 直接加，
  同一个奇物加几次都行（列表里会显示成 `×3`）。
- 「全部移除」：一键清空本局奇物。
- 添加**不消耗奇物池、不改局外图鉴、也不会顺带解锁别的奇物**；移除走游戏自己的 `RemoveRelic`，
  会把奇物挂在战斗上的效果一起撤掉，不会留下「已经没了但加成还在」的幽灵效果。
- 增删立刻同步到游戏里的奇物栏和安全点那面奇物墙，存档时跟着奇物列表一起存，读档后还在。
- 只能改本局，不能凭空给营地 / 局外加奇物（那里本来就没有奇物管理器）。

**设置**
- 工位显示（v0.2.8 定案）：修「设备的工位格子不显示 / 放不了人」。
  - **真正的病因在「设备免疫异常状态」，不在工位本身**（见下面 v0.2.8 更新记录）。
    工位相关的三层（数据 / 绑定 / 显示）经日志验证一直是好的，保留这段逻辑只是当保险和诊断用。
  - 一个格子要能放人，得同时过四层：**① 设备有工位数据** → **② 格子和工位绑上** →
    **③ 格子是激活的** → **④ 先点选旅人再点格子**。任何一层断了，表现都是「空占位框 + 淡色人形剪影、点上去没反应」。
    ④ 层的失败是**静默**的（游戏代码直接跳过，不报错不提示），所以看起来像「格子坏了」——
    放人之前记得先在底部点一下旅人头像。
  - 开启「工位格子常显」（默认开）后，每秒把 ①②③ 三层都补齐一遍：
    缺工位数据就按设备配置补建、格子没绑工位就绑上、格子被关掉就打开、
    实在没工位数据可绑的死格子直接藏掉（不显示假格子）。
  - 「立即修复」手动触发一次；「写诊断到日志」把每台设备、每个格子、每个装备面板槽位的
    真实状态写进 `BepInEx/LogOutput.log`（统一前缀 `[工位诊断]`）。
    （「一键上工位」和「自动补满空工位」v0.3.0 起挪到「旅人」页 —— 它安排的是旅人，放那边更好找。）
  - 只影响格子显不显示 / 能不能绑上，不碰任何战斗数值。
- **隐藏安全点的奇物表**（v0.3.0 新增，在「显示」卡片里）：
  - 「奇物表」= 进安全点（撤离界面）时贴在屏幕边上的那面奇物墙，一格一个奇物图标。
    奇物越多铺得越宽（7 列一排，数量越多排数越多），攒到几十个会把背景和撤离按钮全挡住。
  - 打开开关后这块直接消失，背景、撤离按钮、金币、选路 UI 全部正常。
  - 只是把那个窗口藏起来：奇物的数量、效果、存档一点不受影响，关掉开关立刻恢复显示。
  - 换场景 / 重进安全点时游戏会重建这个窗口，Mod 会自动再藏一次，不用每次手动关。
  - 面板上有一行诊断，会写「已隐藏 N 个奇物窗口」或「当前场景没有奇物表」。
- 改键、满资源目标值、系统字体开关、隐藏安全点奇物墙、工位格子常显、环境诊断（含各开关的当前状态）。

**注意事项**
- 营地资源属于存档数据，改完要回营地或存档才会落盘，直接退游戏会丢。
- 局内金币 / 车辆耐久 / 车速只在本局有效，回营地结算后才写进存档。
- 「不会晕车」「设备免疫异常」「自动补满空工位」「隐藏安全点的奇物表」会写进
  `BepInEx/config/onewaytickets.resedit.cfg`，重启游戏仍然生效；
  「无限耐久」和「车速锁定」只在本次运行内有效，重开一局要重新确认。
- 面板是覆盖层，点面板时底下的游戏 UI 有可能也被点到；把面板拖到空白处用最省事。
- 仅供单机自娱，别拿去联机或传播修改后的存档。

## 更新记录

### 2026-10-27 · v0.5.0

游戏在 2026-10-27 更新了一版（Steam 文件夹从「再再启程 One Way Tickets」改成 `Onewaytickets`，
Data 目录变成 `One Way Tickets_Data`）。这次先逐文件比对了新旧反编译结果，再补功能。

**兼容性核对结论**：奇物、安全点、背包、设备、工位、旅人、营地这几块的类**全部没有改动**；
游戏自己顺手修了三处我们以前打过补丁的地方（`DeviceMgr.InstallDevice` 现在会自动注册工位、
`CubiclesMgr.AddCubicle` 加了去重、`HighLightCubicles` 补了空引用判断），
所以 Mod 里那套工位修补逻辑现在只是保险，不会和游戏打架。

- **新增「奇物」页签**：局内自由增删奇物，详见上面「奇物」一节。
- **修掉自动补位刷屏**：游戏更新后日志里每 2 秒一条
  `自动补位出错：Object reference not set`。原因是营地 / 主菜单没有旅人管理器，
  而 Mod 调的游戏静态工具方法不判空。现在先确认两个管理器都在才动手，
  并且同一类错误只记一次日志，不再把 `LogOutput.log` 刷满。
- **工程里的游戏路径改成新目录**（`OneWayTicketsMod.csproj` 的 `GameDir`）。
  不重新编译的话，旧 dll 调 `TakeCharacterToFront(Character)` 会抛 `MissingMethodException`
  —— 游戏这次给这个方法加了可选参数，签名变了，所以**必须用新版本重新编译**才能用。
- 顺带修了奇物页两处布局：行内按钮被推到可视区外看不见（营地页踩过同一个坑）、
  状态条多一个指标后溢出窗口。

### 2026-10-25 · v0.4.1

清理版：去掉一个帮倒忙的功能，面板上那些啰嗦的说明也一并收掉。

- **删掉「设置 → 交互 → 面板打开时挡住游戏点击」**。它原本是面板可见时禁用游戏的 UI 输入模块，
  防止点面板顺带点到底下的按钮；但实测开了反而容易让游戏 UI 卡住不动，弊大于利，
  直接当没这个功能（`UiInputGuard` 模块、`ClickGuard` 配置项一起移除）。
  现在点面板可能会穿透到下面的游戏 UI，把面板拖到空白处用就行。
- **面板说明文字精简**：每张卡片只留一句「这功能干什么」，删掉了实现细节、版本沿革、历史 bug 之类的长段落。
- 分享包里不再附带 `Mod修改内容说明.md`（安装说明.txt 里已经有一份功能一览）。

### 2026-10-25 · v0.4.0

新增「伙伴休息所」卡片：把**没见过**的特殊伙伴点亮 / 直接收下。

**为什么需要它**
- 营地「伙伴休息所」里，没见过的伙伴是一张黑色剪影，鼠标移上去只显示「？」，点了没反应。
- 依据：`SingleCampCharacterView.update_view_state()`（`Decompiled/Camp/Camp.Character/SingleCampCharacterView.cs:48-71`）
  用 `joined_once_character_list` 判断「见过没」：不在名单里 → `view_state = 2`，点击直接被忽略。
  只有「见过」（局内让他加入过队伍一次）才会变成 `view_state = 1`，这时才能点开成本面板解锁。
- 特殊伙伴（`role.special == true`，共 20 名：阿贝尔、阿飞、雷锵锵、响当当、阿婵、阿墩、工头、格林尼、
  搞事、小敏、王亨利、凯文、爽爽、古神、光、波仔、利尔、小壳、米拉、大运）只能靠休息所收人——
  `CharacterMgr.AddCharacter`（`CharacterMgr.cs:130-140`）自动写好友名单时带 `!special`，局内入队不算数。

**新增的两个操作（「旅人」页 · 伙伴休息所卡片）**
- 「全部标记为已见」/ 每行「标记已见」：把 `joined_once_character_list` 补上，
  休息所里的黑格子立刻变成正常立绘、可点开成本面板。**之后仍要按正常流程花科技 / 资源收人**，
  资源消耗和「初来乍到」成就的判定都不变。覆盖全部角色（特殊伙伴 + 普通旅人，休息所里两类格子都有），
  教程角色 15000「拾光」和无立绘的占位条目除外。
- 「特殊伙伴全收下」/ 每行「收为伙伴」：直接写 `friend_character_list`，
  等于在休息所点了「解锁」但不扣资源。下次读档时游戏的查漏补缺会把「初来乍到」成就补给你。
  只对特殊伙伴生效——普通旅人局内入队时游戏自己就会记，没有「花资源收人」这套流程。
- 列表会实时显示每位角色的状态：未见过 / 已见未收 / 已是伙伴，并标出是特殊伙伴还是普通旅人。
- 改完会立刻刷新休息所界面（`CampCharacterRestRoom.UpdateView()`），不用重开面板或重进营地。

### 2026-10-25 · v0.3.0

两件事：把工位相关的按钮放回它该在的页面，并且终于能把安全点那面奇物墙关掉了。

**1. 隐藏安全点的奇物表（新功能，「设置 → 显示」里）**
- 之前进安全点时，屏幕边上那面奇物墙会随奇物数量一路铺开（7 列一排），
  奇物多了直接把背景和撤离按钮挡住。
- 现在有个开关，打开后这块整个隐藏；关掉立刻恢复。
- 依据：`SafeAreaView.relic_window`（`Decompiled/World/World.SafeArea/SafeAreaView.cs:57`）指向
  `RelicMgrWindowView`，而它**只做「有奇物滑进来 / 没奇物滑出去」的位移动画**
  （`RelicMgrWindowView.cs:53-60`），格子内容全部来自 `RelicMgr.relic_list`

### 2026-10-24 · v0.2.3

修「开启『设备免疫异常状态』之后，一进安全点就黑屏」。

**真正原因（已从日志里拿到完整堆栈）**

- 于是 `immue` 状态 + 空 emergency → `NullReferenceException`，
  异常穿出 `IBlackScreenCoroutine`，协程直接终止：
  黑幕永远停在 alpha=1，`ban_esc` 也一直是 true。

  协程要先淡入约 0.6 秒才走到 `safe_area.Init()`，这个时间足够还原。
- 安全区本来也没有战斗，不需要免疫；离开安全区后会自动重新钉上。

- 安全区里「锁定车速」也停手了。安全区不跑 `CaravanMover` 物理，

### 2026-10-24 · v0.2.0

按需求新增三个功能：

1. **旅人不会晕车**（「旅人」页）
   - 游戏机制：`CharacterMgr.tick` 每物理帧用车辆纵向加速度算冲击力，
     超过 `role.coma_g` 阈值后按概率让旅人进入 `Coma`（昏迷）。
     全游戏只有 `Character.ApplyShockForce` 一处会创建昏迷，所以在这里做前置补丁。
   - 效果：车辆颠簸、设备受击震动都不再让旅人晕倒；附带「全部唤醒」按钮。
   - 开关持久化到配置文件。

2. **设备免疫异常状态**（新增「设备」页）
   - 游戏机制：燃烧 / 机械故障 / 腐蚀 / 缠绕 / 潮湿五种异常，唯一入口是
     `Device.ITarget.applied_outlier`（显式接口实现，编译后名字是 `World.ITarget.applied_outlier`）。
   - 效果：所有施加异常的入口都被跳过，设备永远停在「正常」；
     附带「全部清除」（走 `Device.EnterSafeArea`，图标会一起消失）和「设备列表」。
   - 只免疫异常，普通掉血仍生效。
   - 开关持久化到配置文件。

3. **车辆速度：直接设置 + 锁定**（「局内」页）
   - 游戏机制：车速就是 `WorldContext.caravan_velocity`，
     `CaravanMover_Run.do` 每帧 `velocity += acc/120` 后按 `velocity.x` 推进，
     **没有速度上限字段**，所以「保持最大值」只能靠每帧钉住。
   - 效果：输入框直接设置；「取当前 / 取最高」一键填值；「锁定车速」每帧写回目标值（只在 Run 状态生效）。

其它调整：

- 状态条新增「车速」；概览页新增「车速 / 昏迷旅人 / 异常设备」三行。
- 旅人列表的状态从显示类名（`Coma`）改为中文（昏迷 / 亢奋）。
- 补丁挂载改为逐个 try/catch：单个补丁点失效不会连带其它功能一起不可用。
- 新增 `_work/screen_tool.py`：纯 ctypes 的截图 / SendInput 点击工具，用于本机验证。
