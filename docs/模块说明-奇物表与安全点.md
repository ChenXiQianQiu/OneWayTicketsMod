# 模块说明 · 奇物表与安全点

对应代码：
- `src/OneWayTicketsMod/Game/RelicWindowService.cs`（隐藏奇物表）
- `src/OneWayTicketsMod/UI/TabSettings.cs`（开关放在「设置 → 显示」）
- `src/OneWayTicketsMod/Plugin.cs`（配置项 `隐藏安全点的奇物表`）

## 1. 玩家说的「奇物表」是哪块 UI

就是**进安全点（撤离界面）时贴在屏幕边上的那面奇物墙**：一格一个奇物图标，7 列铺开，
奇物越多铺得越宽，攒到几十个时会从屏幕左边一路铺到屏幕顶，把背景和「撤离」按钮全挡住。

这一屏的三个元素都来自同一个脚本 `Decompiled/World/World.SafeArea/SafeAreaView.cs`：

| 界面元素 | 字段 | 行号 |
|---|---|---|
| 奇物墙 | `relic_window`（`RelicMgrWindowView`） | 57 |
| 撤离按钮 | `end_button` | 39 |
| 金币数字 | `coin_text` | 47 |

## 2. 奇物窗口是纯展示，可以整个关掉

三条依据：

1. `RelicMgrWindowView.cs:53-60`
   `UpdateWindowPosByRelicCount()` 只做一件事：按 `relic_list.Count` 把窗口在
   `position_in` / `position_out` 之间滑动（有奇物滑进来、没奇物滑出去）。
   **它不读也不写任何游戏状态。**
2. `RelicMgrView.cs:92-107`
   `ins_relic()` 只是按 `row_cnt = 7`、`init_row = 3` 生成格子：
   行数 = `max(ceil(数量 / 7), 3)`。格子内容来自 `RelicMgr.relic_list`，窗口自己不持有数据。
3. `RelicView.cs:56-76`
   单个格子只在 `OnPointerEnter` 时弹 `infoview` 说明，没有常驻的浮层。

所以隐藏方式就是 `GameObject.SetActive(false)`：奇物的数量、加成、存档全都不动，
只是不画这面墙。对比之下，「设备免疫」「车速锁定」这类功能都要动运行时数据，
隐藏奇物表是少数**零风险**的开关。

## 3. 实现（`Game/RelicWindowService.cs`）

```
Hidden = true
  └── Tick()（每 0.5 秒，挂在 PanelHost.OnTick 上）
        └── Apply()
              ├── Resources.FindObjectsOfTypeAll<RelicMgrWindowView>()   ← 要能找 inactive 的
              │     └── 过滤掉 prefab 资源：go.scene.IsValid() && go.scene.isLoaded
              ├── Hide(window.gameObject) + 记进 HiddenObjects
              └── 兜底：不在窗口下面的 RelicMgrView 也一起收掉
```

几个要点：

- **每 0.5 秒补一次**：换场景 / 重进安全点时游戏会重建窗口，一次性的 `SetActive(false)`
  顶不住，必须轮询「又冒出来就再关掉」。
- **`Resources.FindObjectsOfTypeAll`**：窗口被我们关掉之后就是 inactive 状态，
  普通 `FindObjectsOfType` 找不到它；同时这个 API 会返回 prefab 资源，
  所以要用 `go.scene.IsValid()` 把资源排掉。
- **只恢复自己关掉的**：`HiddenObjects` 列表记录本 Mod 关过的对象，
  关开关时逐个 `SetActive(true)`。换场景后对象已被销毁（Unity 的「假 null」），`go != null` 直接跳过。
- **兜底分支**：万一某个版本里格子不是挂在窗口下面，只关窗口会留下一条没背景的格子带，
  所以额外把「不在任何窗口下面」的 `RelicMgrView` 也一起收掉。

## 4. 怎么验证

1. 面板「设置 → 显示」打开「隐藏安全点的奇物表」，下面那行诊断会写
   `已隐藏 N 个奇物窗口（累计关闭 M 次）`。
2. 进安全点：奇物墙应该立刻消失，撤离按钮、金币、选路 UI 都正常。
3. 关掉开关：奇物墙立刻回来，数量与隐藏前一致（说明没动 `relic_list`）。
4. 换一个安全点再进一次：应该还是隐藏状态（验证轮询生效）。

如果诊断行一直写「当前场景没有奇物表」，说明当前不在安全点场景
——这个窗口只在安全点存在，战斗场景里本来就没有它。

## 5. 为什么没做「奇物表折叠 / 只显示前 N 个」

用户的需求是「别挡住界面」，隐藏整块最直接。
折叠需要接管 `RelicMgrView.ins_relic()` 的生成逻辑（它每次增删奇物都会全部重建格子），
改动面比隐藏大得多，收益也小。真要中间态，后续可以在 `RelicWindowService` 里
按 `row_cnt` 截断 `relic_views` 的显示，但那时要自己处理 `notify_add_rellic` 的重建时序。
