# 模块说明 · 奇物表与安全点

对应代码：
- `src/OneWayTicketsMod/Game/RelicWindowService.cs`（隐藏奇物表）
- `src/OneWayTicketsMod/Game/RelicEditService.cs`（v0.5.0 新增：局内自由编辑奇物）
- `src/OneWayTicketsMod/UI/TabRelic.cs`（v0.5.0 新增：「奇物」页签）
- `src/OneWayTicketsMod/UI/TabSettings.cs`（隐藏奇物表的开关放在「设置 → 显示」）
- `src/OneWayTicketsMod/Plugin.cs`（配置项 `隐藏安全点的奇物表`）

## 1. 玩家说的「奇物表」是哪块 UI

就是**进安全点（撤离界面）时贴在屏幕边上的那面奇物墙**：一格一个奇物图标，7 列铺开，
奇物越多铺得越宽，攒到几十个时会从屏幕左边一路铺到屏幕顶，把背景和「撤离」按钮全挡住。

这一屏的三个元素都来自同一个脚本 `Decompiled/World/World.SafeArea/SafeAreaView.cs`：

| 界面元素 | 字段 | 行号 |
|---|---|---|
| 奇物墙 | `relic_window`（`RelicMgrWindowView`） | 57 |
| 撤离按钮 | `end_button` | 39 |
| 金币数字 | `coin_text` | 47 |

## 2. 奇物窗口是纯展示，可以整个关掉

三条依据：

1. `RelicMgrWindowView.cs:53-60`
   `UpdateWindowPosByRelicCount()` 只做一件事：按 `relic_list.Count` 把窗口在
   `position_in` / `position_out` 之间滑动（有奇物滑进来、没奇物滑出去）。
   **它不读也不写任何游戏状态。**
2. `RelicMgrView.cs:92-107`
   `ins_relic()` 只是按 `row_cnt = 7`、`init_row = 3` 生成格子：
   行数 = `max(ceil(数量 / 7), 3)`。格子内容来自 `RelicMgr.relic_list`，窗口自己不持有数据。
3. `RelicView.cs:56-76`
   单个格子只在 `OnPointerEnter` 时弹 `infoview` 说明，没有常驻的浮层。

所以隐藏方式就是 `GameObject.SetActive(false)`：奇物的数量、加成、存档全都不动，
只是不画这面墙。对比之下，「设备免疫」「车速锁定」这类功能都要动运行时数据，
隐藏奇物表是少数**零风险**的开关。

## 3. 实现（`Game/RelicWindowService.cs`）

```
Hidden = true
  └── Tick()（每 0.5 秒，挂在 PanelHost.OnTick 上）
        └── Apply()
              ├── Resources.FindObjectsOfTypeAll<RelicMgrWindowView>()   ← 要能找 inactive 的
              │     └── 过滤掉 prefab 资源：go.scene.IsValid() && go.scene.isLoaded
              ├── Hide(window.gameObject) + 记进 HiddenObjects
              └── 兜底：不在窗口下面的 RelicMgrView 也一起收掉
```

几个要点：

- **每 0.5 秒补一次**：换场景 / 重进安全点时游戏会重建窗口，一次性的 `SetActive(false)`
  顶不住，必须轮询「又冒出来就再关掉」。
- **`Resources.FindObjectsOfTypeAll`**：窗口被我们关掉之后就是 inactive 状态，
  普通 `FindObjectsOfType` 找不到它；同时这个 API 会返回 prefab 资源，
  所以要用 `go.scene.IsValid()` 把资源排掉。
- **只恢复自己关掉的**：`HiddenObjects` 列表记录本 Mod 关过的对象，
  关开关时逐个 `SetActive(true)`。换场景后对象已被销毁（Unity 的「假 null」），`go != null` 直接跳过。
- **兜底分支**：万一某个版本里格子不是挂在窗口下面，只关窗口会留下一条没背景的格子带，
  所以额外把「不在任何窗口下面」的 `RelicMgrView` 也一起收掉。

## 4. 怎么验证

1. 面板「设置 → 显示」打开「隐藏安全点的奇物表」，下面那行诊断会写
   `已隐藏 N 个奇物窗口（累计关闭 M 次）`。
2. 进安全点：奇物墙应该立刻消失，撤离按钮、金币、选路 UI 都正常。
3. 关掉开关：奇物墙立刻回来，数量与隐藏前一致（说明没动 `relic_list`）。
4. 换一个安全点再进一次：应该还是隐藏状态（验证轮询生效）。

如果诊断行一直写「当前场景没有奇物表」，说明当前不在安全点场景
——这个窗口只在安全点存在，战斗场景里本来就没有它。

## 5. 为什么没做「奇物表折叠 / 只显示前 N 个」

用户的需求是「别挡住界面」，隐藏整块最直接。
折叠需要接管 `RelicMgrView.ins_relic()` 的生成逻辑（它每次增删奇物都会全部重建格子），
改动面比隐藏大得多，收益也小。真要中间态，后续可以在 `RelicWindowService` 里
按 `row_cnt` 截断 `relic_views` 的显示，但那时要自己处理 `notify_add_rellic` 的重建时序。

# 局内自由编辑奇物（v0.5.0）

## 1. 数据在哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 本局持有的奇物 | `RelicMgr.relic_list`（`List<Relic>`） | 每项是一个行为对象，`relic.desc` 指向 `relic` 表记录 |
| 全部奇物定义 | `AutoCodes.relics.records`（`Dictionary<string, relic>`） | key 是 id 字符串，共 195 条 |
| 奇物池状态 | `RelicMgr.relic_museum`（`RelicMuseum`） | `remain_cnt` 剩余次数、`lock_stage` 解锁阶段，商店/掉落用 |
| 局外图鉴 | `CommonContext.relic_owned` | 营地图鉴里"见过/拥有过"的记录 |
| 存档 | `Save_DS.relic_datas` | 存档时遍历 `relic_list` 写进去（`Save_DS.cs:90-92`） |

`RelicMgr` 由 `RelicPD`（`World.Relic/RelicPD.cs:35`）在局内创建，Mission 里挂名 `"RelicMgr"`，
所以**营地和主菜单没有它** —— 面板在局外会显示"读不到奇物管理器"。

## 2. 为什么不用游戏现成的两个公开入口

`RelicMgr` 有两个看起来正合适的 public 方法，但都有副作用：

| 方法 | 副作用 |
|---|---|
| `CreateRelicAndAdd(id)` | 走 `add_relic`，会触发 `BattleContext.get_relic_event`，还会调 `relic_museum.GetRelic` 扣池子 |
| `CreateRelicAndAddDirectly(id)` | 不触发事件，但仍先调 `relic_museum.GetRelic` → 扣 `remain_cnt` + 按 `lock_change` 改**其它奇物**的 `lock_stage` |

「自由编辑」不该顺手改奇物池和别的奇物的解锁状态，所以添加走的是读档那条路
（`RelicPD.cs:46` 用的就是它）：`CreateRelic(id)` 造对象 → 自己塞进 `relic_list` →
`relic.Get()` 挂效果 → 通知各视图。这正是 private 的 `add_relic_directly` 的三步，
而 `views` 是 `Model<,>` 基类的 public 字段，所以不用反射也能照做。

## 3. 移除必须走 `RemoveRelic`

奇物在 `Get()` 里会往全局挂委托，例如 `Relics/Relic_Ammo_Hail.cs:16-20`：

```csharp
mgr.ranged_add_tick_event += add_event;
```

只从 `relic_list` 里删掉，这个委托还在，效果会继续触发（幽灵加成）。
`RelicMgr.RemoveRelic(Relic)`（:351-359）里 `relic.Drop()` 就是干取消订阅这件事的，
所以移除一律调它，不自己 `relic_list.Remove`。

## 4. UI 同步

`add_relic_directly` / `RemoveRelic` 都会 `notify_add_rellic` / `notify_remove_rellic`，
`RelicMgrView` 收到通知后**整表重建**格子（`RelicMgrView.cs:40-58`：先 Destroy 所有 `relic_views` 再 `ins_relic()`），
所以增删后游戏内奇物栏和安全点奇物墙立刻跟着变，不需要额外刷新。
实测：加 1 个 → 奇物栏多一个图标；加 3 个同名 → 显示 `×3`；全部移除 → 奇物栏清空。

## 5. 面板实现要点

- 全表 195 条**必须缓存**：`AutoCodes.relics.records` 每次访问都会走 `ExcelAnalyzer.init`
  （内部 `Assembly.Load`），OnGUI 一帧画好几遍，不缓存会明显卡帧。
- 名称走 `Localization_Utility.get_localization(relic.name)`，查不到时它返回 key 本身，
  所以表里那些测试奇物（`zoommelee` / `titan` / `difficult` / `lucky`）会显示成英文标识符 —— 这是数据表本来的样子。
- 行内按钮**不能靠 `FlexibleSpace` 右对齐**：外层滚动区可见宽度比布局宽度窄，
  被推到最右的按钮会落到可视区外（营地页「撤下」、这里第一版的「+1/+3」都踩过）。
  一律改成固定宽度、紧跟在前面的标签后面。

## 6. 怎么验证

1. 局内按 F1 →「奇物」页，能看到「本局奇物（N 种 · M 个）」。
2. 下面「添加奇物」搜任意名字 → 点 `+1`：上方列表立刻多一行，游戏右侧奇物栏多一个图标。
3. 点 `+3`：列表显示 `×3`。
4. 点某行「移除」：该行消失，奇物栏同步少一个。
5. 「全部移除」：列表清空、奇物栏清空。
6. 退出再读档：改动过的奇物应该还在（`Save_DS` 存的是 `relic_list`）。
