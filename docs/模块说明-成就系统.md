# 模块说明 · 成就系统（Steam Achievements）

> 依据：`Decompiled/Commons/Commons.Steam/*`、`Decompiled/Camp/Camp.Character/CampCharacterRestRoom.cs`、
> `Decompiled/World/World.Characters/CharacterMgr.cs`，以及从 `db` bundle 里解出来的 `role` / `table_l10n` 表。

## 1. 实现位置

| 文件 | 作用 |
|---|---|
| `Commons.Steam/SteamAchievements.cs` | 唯一的解锁入口 `Unlock(apiName)`；带排队重试（Steam 未就绪 / `SetAchievement` 失败 → 每 5 秒重试，成功后 `StoreStats`） |
| `Commons.Steam/SteamManager.cs` | Steamworks 初始化，`IsInitialized` 是上面那套重试机制的前置条件 |
| `Commons.Steam/AchievementCatchUp.cs` | **查漏补缺**：读档时按存档内容反推该给哪些成就（`Check()`），以及建建筑时补发（`CheckBuilding()`） |

`SteamAchievements.Unlock` 内部用 `HashSet` 去重，重复调用无副作用；Steam 不可用时只是排队，不会丢。

## 3. `GAME_FIRST_FRIEND`（Steam 显示「初来乍到 / 结交一名特殊伙伴」）

### 3.1 判定链

1. `CampCharacterRestRoom.UnlockCharacter()` 是玩家点「解锁」按钮的回调；
2. 扣科技成本（`Camp_Tech_Helper.Afford(record.cost)`）后把角色塞进 `CommonContext.friend_character_list`；
3. 再查 `roles[select_character_id].special`，为 `true` 才 `SteamAchievements.Unlock("GAME_FIRST_FRIEND")`。

所以**只有「伙伴休息所」里的这一次点击能解锁**，其它任何让角色入队的路径都不会。

### 3.2 「特殊伙伴」是数据表里的 `special` 标记

`role` 表（`Assets/Resources_moved/db/role.asset`）共 33 条，字段序为
`id, name, settings, mission_txt, special, friend, portrait_small, …`：

| 段 | special | friend | 说明 |
|---|---|---|---|
| `15999` 神秘少女 | 空 | 空 | 占位/剧情角色，不在任何名单里 |
| `15000` 拾光 | **true** | **true** | 主角（教程角色，`Config.tutorial_role_id`）。`AchievementCatchUp` 里**显式排除** |
| `15101`~`15120` | **true** | false | **20 名特殊伙伴**，成就认的就是这一批 |
| `15201`~`15401` | false | false | 普通旅人，局内入队即进 `friend_character_list`，不给成就 |

`15101`~`15120` 中文名：阿贝尔、阿飞、雷锵锵、响当当、阿婵、阿墩、工头、格林尼、搞事、小敏、
王亨利、凯文、爽爽、古神、光、波仔、利尔、小壳、米拉、大运（任意一位即可）。

### 3.3 为什么「见过」是前置条件

`SingleCampCharacterView.update_view_state()`：

- `joined_once_character_list` 不含该 id → `view_state = 2`，黑色立绘 + `unknown_tip`，**点击被忽略**；
- 含该 id 但 `friend_character_list` 不含 → `view_state = 1`，正常立绘，可点开成本面板；
- 两者都含 → `view_state = 0`，已解锁。

也就是说，必须先在世界里让这名特殊伙伴**加入过队伍一次**（`CharacterMgr.AddCharacter` 会写
`joined_once_character_list`；特殊角色不会被写进 `friend_character_list`），回营地才能在
「伙伴休息所」里花钱把他留下来。

### 3.4 容易踩的点

- 局内特殊角色入队 ≠ 成为伙伴：`CharacterMgr.cs:136` 的自动入名单带了 `!special` 条件，是故意的。
- 建筑「伙伴休息所」是 `building 670004`（同时对应 `BUILDING_NPC` 成就），需要科技 `650040/650041/650042`（1~3 级）才能解锁更多位置。
- 已经有特殊伙伴但没弹成就（例如旧版本解锁的）→ 下次读档时 `AchievementCatchUp.Check()` 会补发；
  但如果 `role_all_unlock` 开着，补发会被跳过（防止把调试数据当成真进度）。

## 4. 数据表离线提取（查任何表都能用）

数据表不是明文文件，走的是 Addressables + `BinaryFormatter`：

```
StreamingAssets/aa/StandaloneWindows64/db_assets_all_*.bundle
  └─ MonoBehaviour「role」/「tech」/「building」…（m_Name 即表名）
       └─ byte[] → EX_Utility.byte2object → BinaryFormatter.Deserialize → Dictionary<string, List<object>>
```

工具（都在 `_work/`）：

```bash
# 1. 从 bundle 里抠出序列化流（UnityPy 解包 + 找 BinaryFormatter 头 00 01 00 00 00 FF FF FF FF 01 00 00 00 00 00 00 00）
python _work/extract_db_table.py role          # 也可传 bundle 路径
python _work/extract_db_table.py table_l10n    # 本地化表在 db_localization bundle
# 2. 反序列化并导出 TSV
cd _work/DbTableDump && dotnet run -- ../../out/role_bf.bin ../../out/role.tsv
```

注意：

- `ExcelAnalyzer` 是按**字段声明顺序**把 `List<object>` 逐位塞进记录的，所以 TSV 的列序就是
  `AutoCodes/<表名>.cs` 里的字段序；导出时我在最前面多插了一列 key，取字段要整体 +1。
- `table_l10n` 的列序：`key, id, CN, TW, EN, …`，取中文名用第 3 列。
- 只有 `db` / `db_localization` 两个 bundle 里有表；其余 bundle 是美术与预制体。
