**晕车（冲击昏迷）的完整链路**：

```
CharacterMgr.tick()                        CharacterMgr.cs:61-72
  └── shockForce = |character_focus_aceleration.y|   ← 由车辆纵向加速度算出
        └── Character.ApplyShockForce(shockForce)    Character.cs:221
              ├── 先看 isImmuneToStun / state != null / coma_free_ticks > 0 → 直接返回
              ├── 阈值 = desc.coma_g * (1 + global_coma_resist_pts/1000)
              ├── 未超过阈值 → 只是说句台词
              └── 超过阈值 → 按概率 state = new Coma(this, ...)   ← 全游戏唯一的 Coma 来源
```

`CP_Step_Up`（旅人特性「挺身而出」）在设备受击时也调 `ApplyShockForce`（`CP_Step_Up.cs:24-33`），
所以拦掉这个方法会**同时**免疫「颠簸晕车」和「设备受击震晕」。实现见
`src/OneWayTicketsMod/Patches/CharacterShockPatch.cs`。

## 8.1 进安全区黑屏：协程被异常打断

`WorldSceneRoot.IBlackScreenCoroutine`（`World/World/WorldSceneRoot.cs:441-496`）是**一条长协程**：

```
alpha 0→1 → 清怪 → safe_area.Init() → 旅人 EnterSafeArea → 设备 EnterSafeArea
          → Safe_Area_Helper.enter_after_calc()（存档）→ alpha 1→0 → SetActive(false)
```

中途任何一步抛异常，协程立即终止：`black_screen` 停在 `alpha = 1`，
`ban_esc` 停在 `true`（ESC 也失效），而游戏逻辑（对话 / AI / 音频）照常跑。
**表现就是「整屏黑，但还能按 F1 打开 Mod 面板」。**

已知会把这条协程打断的地方（v0.2.3 修的就是第 1 条）：

| 触发点 | 原因 |
|---|---|
| `safe_area.Init()` → `init_device` → `EquipmentMgr.Init` → `EquipSlot.set_panel` → `DeviceUiView.attach` | `Device.attach` 里 `if (owner.state != normal) show_emergency(owner.device_emergency);`，`immue` 状态下 emergency 是 null，`show_emergency` 末尾 `de.init()` 没判空 → NRE |
| 任何 `device_emergency` 与 `state` 不一致的情况 | 同上，`views` 里若含已销毁的 view 也会 NRE |

排查手法：`BepInEx/config/BepInEx.cfg` 里把 `WriteUnityLog` 改成 `true`，
Unity 侧的异常和 `Debug.Log` 就会写进 `BepInEx/LogOutput.log`，堆栈直接指到出事的行。

## 9. 重要坑：Harmony 补丁在本作不执行

**实测结论（v0.2.1）**：BepInEx 的 Harmony 补丁在本作里虽然「挂载成功」，
但目标方法被调用时补丁体**完全不执行**。`BepInEx/LogOutput.log` 只打印
`补丁已挂载：XxxPatch`，没有任何报错，非常容易误判成生效了。

验证方式：给 `CaravanMover_Run.do` 挂一个计数后置补丁（这个方法是被反射
`GetMethod("do").Invoke` 调用的，不可能被内联），车连续跑十几秒，计数一直是 0。
同一套机制挂的 `Cubicle_Helper.SetCubicle` 日志也一条都没有。

推测原因：Mono 内联 / 程序集加载上下文导致 patch 落到了不生效的副本上
（本作 `CaravanMover` 里还有 `Assembly.Load("World")`，存在多份程序集的可能性）。

**结论**：给这个游戏写 Mod 时，**不要依赖 Harmony 改游戏行为**。可行的替代方案：

| 需求 | 替代做法 |
|---|---|
| 改数值 / 状态 | 直接写游戏对象的 public 字段（如 `caravan_velocity`、`isImmuneToStun`） |
| 持续生效 | 在 `PanelHost.Update` 的常驻回调里轮询回写（如车速锁定、无限耐久） |
| 借游戏机制 | 加游戏自带的词缀 / 属性（如「油门焊死」`CP_Reckless_Driving`） |
| 绕开被拦的操作 | 调用游戏自己的其它入口（如工位分配先 `TakeCharacterToFront` 换到前排，再 `set_worker` / `EnterCubicle`） |

代码里的 `Patches/*.cs` 都还留着，作为「万一以后能用」的加分项，但功能正确性
不依赖它们。

## 10. 备忘：官方调试开关（未使用，但值得记）

`Commons/Config.cs` 里有一批运行期可改的调试开关，正式包里都是 `false`：

| 字段 | 效果 | 应用位置 |
|---|---|---|
| `is_player_invincible` | 玩家/车辆完全免伤 | `Caravan.hurt`、`Widget_Player_Hurt_Context` |
| `all_cc_unlock` | 进营地时解锁全部营地币并设为 9999 | `CampSceneRoot` 初始化块 |
| `device_all_unlock` / `loot_all_unlock` / `enemy_all_unlock` | 解锁全部装置 / 战利品 / 敌人图鉴 | 同上 |
| `is_load_enemys` / `is_load_caravan_speed_low_limit` | 刷怪 / 强制最低车速 | `WorldContext` |

这些字段是 `ScriptableObject` 上的普通 `public bool`，`Config.current` 是静态引用，
运行期赋值即可生效（部分只在场景初始化时读一次）。本 Mod 目前**没有**用到它们，
但要做「无敌」「全图鉴解锁」时这里是现成入口。
