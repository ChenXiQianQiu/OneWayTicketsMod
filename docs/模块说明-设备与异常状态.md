# 模块说明 · 设备与异常状态

对应代码：`src/OneWayTicketsMod/Game/DeviceGuardService.cs`、`src/OneWayTicketsMod/Patches/DeviceOutlierPatch.cs`、`src/OneWayTicketsMod/UI/TabDevice.cs`

## 1. 什么是「设备异常」

`Device.DeviceState`（`Decompiled/World/World.Devices/Device.cs:21-30`）：

| 枚举 | 中文 | 表现 |
|---|---|---|
| `normal` | 正常 | — |
| `immue` | 免疫中 | 刚清掉异常后的短暂无敌，时长 `Config.device_debuff_immue_duration` |
| `fired` | 燃烧 | `DeviceFired`，持续掉血 |
| `stupor` | 机械故障 | `DeviceStupor`，设备停摆 |
| `acid` | 腐蚀 | `DeviceAcid`，持续掉血 |
| `bind` | 缠绕 | `Adherent` 附着，`WorldContext.slow_rate` 上升 |
| `wet` | 潮湿 | `DeviceWet`，攒水滴 |

## 2. 唯一入口：`ITarget.applied_outlier`

```csharp
// Device.cs:795
void ITarget.applied_outlier(ITarget source, string outlier_type, int value)
{
    if (state == DeviceState.immue) return;
    switch (outlier_type)
    {
        case "sharp": break;              // 空分支
        case "flash": break;              // 空分支
        case "blunt": ... state = stupor; // 钝击，按概率
        case "fire":  ... state = fired;  // 还会和 wet 互相抵消
        case "acid":  ... state = acid;
        case "wrap":  ... AddEmergency("wrap", 999f);
        case "water": ... state = wet;    // 也会和 fired 互相抵消
    }
}
```

所有伤害流程最后都会调它（`Enemy_Hurt_Helper`、各 `*Projectile`、`Weather`、
`AdherentMgr`、各 `Device_AI` 的攻击逻辑、控制台 `buffdevice`），
所以**拦掉这一个方法就等于设备永远不会进异常状态**，不用逐个改调用方。

### 为什么补丁不能写死方法名

这是**显式接口实现**，编译后的方法名是 `World.ITarget.applied_outlier`
（带命名空间点号），而且它是 `private virtual`。所以：

```csharp
[HarmonyPatch]
static class DeviceOutlierPatch
{
    // 按后缀反射找，不依赖名字拼写
    static MethodBase TargetMethod() =>
        AccessTools.GetDeclaredMethods(typeof(Device))
            .FirstOrDefault(m => m.Name.EndsWith("applied_outlier", StringComparison.Ordinal));

    [HarmonyPrefix]
    static bool Prefix() => !DeviceGuardService.ImmuneEnabled;
}
```

已用离线反射验证过实际名字：

```
World.Devices.Device → 'World.ITarget.applied_outlier'  private=True virtual=True
```

`Device` 的所有子类（`BasicWheel`、`DScript_Shooter_*`、`Unique_War_Drum` …）
都**没有**重写这个方法（全量 grep 确认），所以补丁对全部设备生效。

> `Boomerang`、`Enemy`、`Caravan` 也各有一份空的 `applied_outlier`，
> 但它们是各自独立实现 `ITarget` 的类型，与设备无关，不用管。

## 3. 只免疫异常，不免疫掉血

`Device.Hurt`（`Device.cs:486`）是另一条链路：

```
ITarget.hurt → Hurt_Calc_Helper.dmg_to_device → Device.Hurt(dmg)
```

伤害照常扣 `current_hp`，扣到 0 会 `Disable()`（设备报废）。
要「设备不掉血」请用「局内」页的**无限耐久**（那是补车辆耐久的）——
设备本体没有轮询修复的开关，因为设备血量每局重建，改了意义不大。

## 4. 一键清除

`DeviceGuardService.ClearAll()` 对每台异常设备调用 `Device.EnterSafeArea()`
（`Device.cs:279`）—— 这正是游戏进安全区时的清理逻辑：

1. `device_emergency` 逐个 `view.notify_remove_emergency(...)` → **UI 图标一起消失**；
2. `state = DeviceState.normal`。

比手动 `state = normal` 安全得多：后者会留下没被移除的 emergency 对象，
下次 tick 的 `CheckEmergency` 会把它又捡回来。

> `DScript_Melee_Charge` / `DScript_Ram` / `DScript_Special_Boomerang`
> 重写了 `EnterSafeArea()`，但都先调 `base.EnterSafeArea()`，所以行为一致。

## 5. 设备列表怎么读

```csharp
SingletonAccess.Mgr<DeviceMgr>("DeviceMgr")   // Mission 里挂名 "DeviceMgr"
  └── slots_device : List<DeviceSlot>
        └── slot_device : Device   // 可能是 null（拆掉了）
```

- 名字：`device.desc.name` 是本地化 key，要过 `Localization_Utility.get_localization`，
  再把 `<sprite ...>` 之类的富文本标签剥掉（IMGUI 不解析）。
- 状态：直接读 `device.state`，由 `TabDevice.StateName` 映射成中文。
- 报废判定：`is_validate == false`（`Disable()` 里置的），列表里用红色显示。

## 6. 已知取舍

| 取舍 | 说明 |
|---|---|
| 缠绕（`wrap`）仍然会生成 `Adherent` 对象 | 补丁拦的是「设备进入 bind 状态」，`AdherentMgr` 自己的附着逻辑不受影响，但设备不会显示缠绕、也不会吃 `slow_rate` 之外的减益 |
| `immue`（免疫中）状态不会被打断 | 补丁对 `immue` 也一样 return，等价于「一直是 normal」，不影响原有免疫计时 |
| 开关持久化 | `Plugin.DeviceImmune` 写进配置文件，重启游戏仍生效 |
