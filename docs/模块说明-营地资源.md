# 模块说明 · 营地资源

对应代码：`src/OneWayTicketsMod/Game/CampCoinService.cs`

## 1. 数据在哪

```
Foundations.Singleton<CommonContext>.m_instance
└── Dictionary<int,int> camp_coins        // id → 持有数量
└── HashSet<int>      unlocked_camp_coins // id 是否解锁（解锁才会在营地 UI 里出现）
```

- 反编译依据：`Decompiled/Commons/Commons/CommonContext.cs`（第 13 / 49 行）
- 读法：`SingletonAccess.Get<CommonContext>()`，**直接读私有静态字段 `m_instance`**。
  不要用 `Singleton<CommonContext>.instance`：那个属性在字段为空时会 `new` 一个出来（`Singleton.cs:20`），
  Mod 在游戏还没进营地时访问就会造出假单例。

## 2. 「解锁」和「拥有」是两件事

这是 CE 版花了很久才定位到的坑：

- 解锁某个营地币 = 往 `unlocked_camp_coins` 里 `Add(id)`，**不会**在 `camp_coins` 里建条目；
- 营地 UI 取数是 `camp_coins.TryGetValue(coin_id, out value)`（`Camp.Coins/CoinInfo.cs:24`），
  取不到就显示 0；
- 所以「已解锁但一次都没获得过」的币（典型是**秘能 6114**）在字典里根本没有 key，
  只改字典拿不到它的地址 → CE 里只能显示 `???`。

本 Mod 的处理：

| 操作 | 行为 |
|---|---|
| `Set(id, value)` | 条目不存在时先补一条 0，同时把 id 加进 `unlocked_camp_coins`（否则营地里看不到这一项） |
| `FillMissing()` | 把所有「已解锁但没有条目」的币补成 0，对应 CE 的「补建未获得的营地币」 |
| `UnlockAll()` | 把 `camp_coins.records` 里所有 id 加进 `unlocked_camp_coins` |
| `FillAll(value)` | 对「已解锁 ∪ 已拥有」的 id 全部设成同一个值 |

## 3. HUD 为什么不会自己变

营地左上角那排资源**不是每帧刷新**的，只在 `Camp.Coins.CoinArea.call()` 被调用时重读
（游戏里由车库 `CampGarage`、休息区 `CampCharacterRestRoom`、装置 `CampDevice` 等操作触发）。
反编译依据：`Decompiled/Camp/Camp.Coins/CoinArea.cs`。

所以写入后必须自己刷一次：

```csharp
var root = CampSceneRoot.instance;      // 不在营地时为 null
root?.coinArea?.call();
```

实现上用「标脏 + 下一帧统一刷」：`Set()` 只置 `_hudDirty = true`，
`CampCoinService.Tick()`（由 `PanelHost.OnTick` 每帧调用）发现有脏就刷一次。
这样批量写 5 个币也只刷一次，不会反复走 `Addressable_Utility.try_load_asset` 重载图标。

## 4. 名字从哪来

`AutoCodes.camp_coin` 的 `name` 是**本地化 key**，不是中文：

```csharp
Localization_Utility.get_localization(record.name)   // → "里程券"
```

- 本地化表可能带富文本（`<sprite name=...>`、`<color=...>`），IMGUI 不解析，必须正则剥掉；
- 拿不到时退回内置表 `6100 里程券 / 6111 食物 / 6112 建材 / 6113 珍宝 / 6114 秘能`；
- 名字按 id 缓存，**只在真正从数据表取到时才缓存**，避免数据表还没初始化时把兜底名钉死。

## 5. 性能注意

`AutoCodes.camp_coins.records` 每次访问都会走 `ExcelAnalyzer.init()`，
内部是 `Assembly.Load("AutoCodes")` + 反射找 `m_records`（`Foundations/Foundations.Excels/ExcelAnalyzer.cs`）。
`OnGUI` 一帧要画好几遍，所以这里做了三层缓存：

1. `NameCache`：id → 名字
2. `_allIds`：数据表全部 id
3. `_listCache`：0.25 秒 TTL 的展示列表，写入时立即失效

## 6. 生效时机

`camp_coins` 属于存档主体 `CommonContext`，回营地或存档时才会落盘。
所以「改完立刻在营地里花掉」是有效的，但**改完不存档直接退游戏**会丢。
